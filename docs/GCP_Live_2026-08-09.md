## Three IAM gaps the scripts do not mention

Each failed once, and each is invisible until you deploy for real:

1. **Cloud Build refused with `PERMISSION_DENIED` despite `roles/owner`.** New
   projects retire the legacy build service account; a build must name one.
2. **The Cloud Run runtime SA had no `secretmanager.secretAccessor`**, so
   `--set-secrets` would have failed.
3. **…and no `cloudsql.client`**, so the socket would not have connected.

`deploy_api.zsh` handles none of these and also omits
`--add-cloudsql-instances`, without which the API cannot reach the database
at all.

## ⚠ `/healthz` is intercepted on this network, and it is not the app

`curl …/healthz` returns a **Google 404 page with no `server` header**, while
`/healthz/` and `/HEALTHZ` both return the app's real 200. `/nonexistent`
returns the app's own empty 404 *with* `server: Google Frontend`.

So the exact lowercase string `/healthz` is being swallowed somewhere between
this machine and Google — a proxy or filter, not Cloud Run and not the code.
It matters because **`deploy_api.zsh` prints exactly that curl as its success
check**, and a fresh operator would read the 404 as a failed deploy and start
debugging a working service.

## ⚠ THE BLOCKER FOR REAL USE: blobs are on the container's local disk

`Program.cs` registers `FileBlobStore` writing to `BLOB_ROOT`
(`/var/lib/robotbrawl/blobs`). On Cloud Run that path is **ephemeral and
per-instance**:

- with `min-instances=0` the disk vanishes when the service scales down, so
  an uploaded snapshot's payload is **gone** and its VALIDATE job can never be
  worked
- with more than one instance, a worker fetching a payload may land on an
  instance that never had it

The upload returned 200 above, which is exactly the problem: it looks like it
worked.

`gcp_bootstrap.zsh` already created `…-snapshots` and `…-replays`, and
**nothing uses them**. A `GcsBlobStore` behind the existing `IBlobStore`
interface is the missing piece — the seam is there, the implementation is
not. Until then this deployment is a working API with a disappearing
filesystem, which is fine for a smoke test and not fine for a player.
