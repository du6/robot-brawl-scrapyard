IT FOUND A REAL BUG ON ITS FIRST RUN, and it was mine, one commit old.

DoEnlist set the confirmation message and THEN called Refresh(), which ends by
setting status to "<n> ranked". Pressing ENLIST showed "8 ranked" and nothing
else: no confirmation, and the no-program warning — the one message that is
only actionable at that exact moment — destroyed.

The same function already carried a comment about this exact failure ("a
status written before the upload is overwritten by its result, which is
precisely how a warning that matters goes unread"). I fixed that case and
introduced the identical bug on the other side of the call. A status line with
two writers and no ordering rule loses the message that mattered, every time.

Fixed by refreshing FIRST and speaking afterwards.

GUI functions from inside OnGUI", which looked like three broken panel states
and was one broken harness. The draw is now serviced from the bench
